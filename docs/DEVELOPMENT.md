# Разработка — VtM20 Kamen & Shamil Edition

Как собрать данные и компендии, проверить и выпустить систему. Описание для игроков — в [README](../README.md).

## Перенос мира с worldofdarkness

```
node tools/migrate_wod.mjs <папка мира> <папка копии> <id копии> "<название>"
```

Создаёт копию мира на этой системе (исходный не меняется): персонажи, Дисциплины и пути, записанные силы и ритуалы, достоинства, недостатки, факты, вторичные способности, опыт, оружие, броня, предметы мира, полоски токенов.

## Пересборка данных и графики

```
python -I tools/build_data.py    # справочник books/Мир Тьмы → data/*.json
python -I tools/make_assets.py   # SVG: кокарда (для модуля Парижа), венок, печать, гильош, иконки
node tools/build_packs.mjs       # компендии packs/* из data/*.json (при остановленном Foundry)
```

Полные тексты книг (`books/**/_текст/`) в репозиторий не входят. Вид и категорию черт из дополнений `tools/merits_extra.py` берёт из английских текстов, а без них — из `tools/merits_en_index.json` (названия, вид, категория; обновляется сам при сборке с текстами). Готовые записи в формате `data/merits.json` лежат в `tools/merits_*_manual.json`: черты старых книг без английского названия, которых нет в V20 (`merits_revised_manual.json`), и клановые черты Тёмных веков и «Самеди» (`merits_clan_manual.json`).

Описания и системы черт берутся из финальной редакции `tools/sources/structure/merits_final.json`. Новую партию аудита (накопительную базу из архива) вливает `tools/merits_batch.py`:

```bash
python -I tools/merits_batch.py <база партии.json> --dry                    # только отчёт
python -I tools/merits_batch.py <база партии.json>                          # архив собран от нашей базы
python -I tools/merits_batch.py <база партии.json> --base <база архива.json> # архив от старой базы: только его изменения
python -I tools/merits_batch.py <база партии.json> --onto                   # базы архива нет: его изменения поверх нашей
```

Скрипт сначала сверяет архив со снимком. Если в архиве нет части наших черт (он собран от старой базы или параллельно с другим архивом той же партии), скрипт останавливается и перечисляет пропавшие по книгам, а не затирает их. С `--base` берётся только то, что архив изменил или добавил относительно своей базы; если ту же черту изменили и у нас, это конфликт и остановка. С `--onto` общие черты берутся из архива, а изменённые перечисляются: если архив старше нашей базы, это может быть откат. Черты сопоставляются по виду, имени, эпохе и линии, внутри — по книге, затем по английскому имени, так что одноимённые черты разных книг не склеиваются, а уточнение книги (партия 26) узнаётся. Ещё скрипт убирает повтор «Описания» в начале «Системы» (ручные разбивки — в `SPLIT`) и приводит кланы к ключам системы (`CLAN_ALIAS`). Полная объединённая база для аудитора — `tools/sources/structure/audit/merits/НАКОПИТЕЛЬНАЯ_БАЗА_после_партии_<N>.json` (последняя; черты гулей в ней — с `ghoul: true`, скрипт отправляет их в набор гулей). Если аудитор прислал только изменения партии (`batch_<N>_added_updated_cards.json`: `added` — новые карточки, `updated` — `index`/`before`/`after`), сначала соберите из прошлой накопительной базы новую (заменить `before` на `after` по индексу, дописать `added`), потом влейте её с `--base <прошлая база>`.

**Грани из книг кредо** (`BOOK_EDGES` в `tools/hunter_data.py`) — вторая пятёрка того же пути с ключом `путь|уровень|книга` (например, `visionary|2|vb`); цена и бюджет — как у основной Грани того же уровня, а «нужна Грань прошлого уровня» закрывает любая Грань пути (`hasPrevEdge` в `module/apps/hunter.mjs`).

**Дампиры** (`tools/dhampir_data.py` → `data/dhampir.json`, «Accursed Heirs: Dhampirs»): концепции, Кровные права, ритуалы Дриримантии, слабости кланов, Дополнения и черты (из аудита партии 32, `tools/sources/dhampir/`). Дампир — гуль с `ghoulType: "dhampir"`, данные — `system.dhampir`; логика листа — `module/apps/dhampir.mjs`. Черты и Дополнения дампиров помечены `dhampir: true` (видит только дампир), черты «только для смертных» — `mortal: true` (смертные и охотники). Путь биотауматургии и силы старейшин из гл. 3 добавляет `dhampir_data.extend_disciplines` при сборке Дисциплин.

У каждой черты в `data/merits.json` есть поля `clan` (ключ из `data/clans.json`) и `sect` (`camarilla`, `sabbat`, `anarchs`); у общих черт они пустые. Клановые черты и черты сект не попадают в общие категории: в мастере создания они в отдельных категориях «Клановые» и «Черты секты» (только клан и секта персонажа; антитрибу и ветви видят черты родительского клана), в библиотеке — своими группами, в компендии — в папках «Клановые достоинства / <клан>», «Клановые недостатки / <клан>», «Черты сект / <секта>».

Пути и ритуалы магии крови сверх основной книги и дополнений V20 собирает `tools/magic_extra.py`: Revised (гайды сект, кланбуки, Storytellers Handbook), 2nd Edition (Players Guide, Players Guide to the Sabbat, городские книги), Blood Magic, Blood Sacrifice и Тёмные века (V20 Dark Ages, Tome of Secrets, Low Clans, Companion, House of Tremere, Dark Ages Storytellers Companion). Повторы отсекаются по английскому названию; приоритет V20 → Revised → 2nd → Тёмные века.

Ритуалы и пути Тёмной Тауматургии, которых нет в книгах справочника (Player's Guide to the Sabbat 1992, Storytellers Handbook to the Sabbat, Sins of the Blood, Dark Ages Companion 1998), собирает `tools/dt_archive.py` из архива конспектов `tools/sources/dark_thaumaturgy_archive/` — с пометкой «пересказ по конспекту, не текст книги» в источнике. MET/OWbN-варианты и фанатская Strigia пропускаются; уже собранное из V20 не дублируется, аналоги подписаны у путей.

Пути Просветления сверх основной книги и Дороги Тёмных веков собирает `tools/paths_extra.py`: Lore of the Clans, The Black Hand, гайды по Шабашу (Revised и 2nd), Revised, V20 Dark Ages, Dark Ages Companion, Road of Heaven, кланбуки Салюбри и Баали, Dark Ages Storytellers Companion и Dark Ages: Vampire (2002). Пути внутри Дороги, у которых в книге перечислены только отличающиеся грехи, получают остальную иерархию и Столп от своей Дороги. Карточки линий, которых нет в книгах справочника, лежат в `tools/clans_manual.json` (сейчас — Сыны Самуила из фанатской «Samedi»).

Комбинированные Дисциплины сверх дополнений V20 собирает `tools/combos_extra.py`: Rites of the Blood, Guide to the Camarilla и Guide to the Anarchs (Revised), кланбуки Revised, Player's Guide to Low Clans и Road of Heaven (Тёмные века). Одна и та же сила в другом переводе (те же требования, без английского названия) перечислена в `SAME` и не дублируется.

Высокие уровни Дисциплин (6–9) и новые силы сверх V20 собирает `tools/powers_extra.py`: Guide to the Camarilla и Guide to the Sabbat (Revised), кланбуки Revised, Player's Guide to High Clans и Low Clans (Тёмные века). Силы из Guide to the Camarilla, у которых в книге нет точного уровня («на каждом из уровней 6–9 — одна способность на выбор»), стоят на 6-м уровне с пометкой. Комбинированные силы из смешанных таблиц кланбуков в Дисциплины не попадают — их собирает `tools/combos_extra.py`.

**Ритуалы по разделам.** `tools/ritual_docs.py` (вызывается из build_data.py после `polish.rituals`) разбирает справочники-пересказы `tools/sources/rituals/<школа>.md` — Тауматургия, Некромантия, Колдовство, Чародейство ассамитов и сетитов, Тёмная Тауматургия, Мистика Бездны — и кладёт в каждый ритуал `data/rituals.json` поле `parts`: `head` (шапка «Уровень · Бросок · Источник»), `desc`, `components`, `effect`, `notes` (прочие разделы `[{title, html}]`) и `ref` (книга и страница); `html` собирается из них заново. Запись справочника — `### [N.] Имя (En) — уровень X`, разделы — `**Описание:**`, `**Компоненты…:**`, `**Эффект…:**` и любые другие; уровень без числа берётся из заголовка раздела `# Уровень N`, из ступени OWbN или по сложности броска. Сопоставление с каталогом — по имени и уровню, затем по английскому названию и «Другим переводам»; названия ритуалов остаются каталожными. Файлы `<школа>-extra.md` добавляют ритуалы, которых в каталоге нет (дубли отсекаются по имени и английским названиям через «;» и «/»), бросок — как у ритуалов школы. В предмете ритуала разделы — поля `description` (шапка и «Описание»), `components`, `effect`, `notes`, `ref`; полный текст для листа персонажа и чата — `ritualHTML` в `module/data/ritual-text.mjs`. Ритуалы персонажей без разделов `migrateWorld` дополняет из справочника по имени.

**«Описание» и «Система».** `tools/text_structure.py` (шаг build_data.py, перед записью) раскладывает силы и черты на два раздела. Источники — `tools/sources/structure/`: `disciplines_v38.json` (снимок базы Дисциплин), `assamite_sorcery.json` (Dur-An-Ki), `docs/*.md` (справочники по Дисциплинам; приставки из `OVERRIDE` — более поздние аудиты, они важнее снимка), `rituals/<школа>__*.md` (проверенные карточки ритуалов поверх `ritual_docs.py`), `descriptions.md` (описания сил, у которых в источнике только механика), `merits_final.json` (финальная редакция черт); `audit/` — таблицы и открытые вопросы аудиторов, в сборку не идут. Черты гулей и падших (`data/merits-ghouls.json`, `demon-merits.json`) пересобирает `python -I tools/text_structure.py`. Сверки с первоисточником, расходящиеся с аудитами, перечислены в шапке файла.

**Оглавление и тексты.** `data/disciplines.json` и `data/rituals.json` — без текстов (имена, уровни, броски); описания и разделы ритуалов — в `data/*-text.json` (`split_texts` в build_data.py, `module/data/text-split.mjs`). Мир при старте ждёт только оглавление (`Codex.load({ texts: false })`), тексты догружаются фоном (`Codex.loadTexts`); `Codex.load()` без параметров ждёт и их. `build_packs.mjs` и `check.mjs` склеивают файлы сами.

**«Обновить из справочника».** `module/apps/codex-refresh.mjs`: предмет на листе находится в справочнике по типу, Дисциплине и уровню, названию и английскому имени (`system.source`); окно показывает, у чего текст отличается, и обновляет отмеченное. Поле `status` записей (пометка аудита) и `edition` сил библиотека показывает метками.

**Линии черт.** У черт и фактов биографии поле `line`: пусто — вампиры, гули и смертные; `demon` — падшие (`data/demon-*.json`); `hunter` — черты смертных охотников из Hunters Hunted II (ставит build_data.py). Библиотека и мастер создания показывают только линию персонажа (`VTM20.traitLine`), в библиотеке и фильтры категорий — только те, что есть в его списке. Компендии разложены по папкам `packFolders` в system.json: Vampire: The Masquerade, Demon: The Fallen, Hunter: The Reckoning (`hunter-merits`).

Справочник падших (`data/demon.json`: Знания, призывы, Дома, Облики, фракции — названия, уровни и пулы, без текста книги) собирает `tools/build_demon.py` из PDF русского издания.

Пути Просветления и Дороги собраны и в компендий-журнал «Пути Просветления» (`enlightenment-paths`): на странице — добродетели, аура, последователи, источник и иерархия грехов; пути Тёмных веков лежат в папках своих Дорог.

Фанатское дополнение «Vampire: Age of the Living Gods» (`tools/alg_extra.py`, `paths_extra.py`): Дисциплина Мортис, Способности эпохи (подсказки во вторичных способностях, `data/abilities.json`), три Факта биографии и восемь Путей Морали — с пометкой «фанатское», видны только с настройкой Dark Ages. Аналоги путей магии крови между школами (Магусы и Дур-Ан-Ки, Акху, Садхана, Ванга, Нахуаллотль, герметические пути Тёмных веков, редакции Укладов кольдунов) подписаны у путей шагом `blood_equiv` в `tools/build_data.py`.

**Контент из Dark Ages.** Пути, ритуалы, силы и комбинированные Дисциплины, достоинства и недостатки Тёмных веков помечены в `data/*.json` полем `era: "darkAges"`. Они видны в мастере создания, библиотеке и на листе только при включённой настройке мира «Контент из Dark Ages» (по умолчанию выключена; от эпохи хроники не зависит). В компендиях они лежат в папках «Тёмные века».

`build_packs.mjs` берёт `classic-level` и версию ядра из установленного Foundry (переменная `FOUNDRY_APP` = папка `resources/app`, иначе известные пути). Компендии в `.gitattributes` помечены как двоичные: иначе на Windows с `core.autocrlf` git портит служебный файл LevelDB `CURRENT` и база не открывается.

## Проверка перед коммитом

`node tools/check.mjs` — синтаксис всех модулей (включая повторные объявления имён), тесты подсчёта броска
и шансов по правилам V20, чтение data/*.json и lang/ru.json, тексты сил и черт (у каждой «Описание» и «Система»,
без служебных пометок справочников и повтора описания в системе), наличие иконок предметов в Foundry, целость
компендиев в индексе git (новый пак нужно добавить в git до проверки), перевод: в `lang/en.json` те же ключи и подстановки `{…}`, что в `lang/ru.json`.
`node tools/packs-fresh.mjs` пересобирает компендии из `data/*.json` и сверяет число записей с закоммиченными (Foundry должен быть остановлен). Обе проверки запускает GitHub при каждом push (`.github/workflows/check.yml`).

Английский интерфейс: имена записей справочника показываются через `VTM20.label(x)` / помощники шаблонов `{{rName this}}` и `{{rAlt this}}` (при английском — `en`, если есть, второе имя — подписью); для предметов на листе английское имя ищет `Codex.enOf(item)`. Связь со справочником — всегда по русскому имени.

`node tools/e2e.mjs` — проверки в запущенном тестовом мире Foundry через Playwright (лист и броски, мастера создания,
толпа, торпор, охота с карты, Маскарад, узы и Винкулум, доход, котерия, летопись, падшие, Привязанные и слуги,
новый и старый мир с модулем Парижа); мир после прогона возвращается как был. Профиль браузера
английский — проверки сравнивают с `game.i18n.localize`, а не с русскими строками.

`node tools/e2e-all.mjs` — тот же полный прогон по группам (каждая — отдельным процессом); `--groups vampire,changeling` — выборочно.

`node tools/e2e-shots.mjs` — снимки-сравнения окон: листы всех линеек (гуль, ревенант, дампир — отдельно), вкладки
подменыша, лист мотли, мастер создания, HUD. Эталоны — `tools/.cache/shots/base/` (локально, не в git; без эталона снимок
сам становится эталоном); отличие больше 0,5% точек — провал и `<имя>.diff.png` с подсвеченными изменениями.
После намеренной правки вида — `node tools/e2e-shots.mjs --update`; выборочно — `--only changeling,motley`.

## Справочник правил

`tools/rules_extra.py` (вызывается из build_data.py) собирает главы «V20_Основные_правила» в data/rules.json;
`node tools/build_packs.mjs rules` — компендий-журнал «Правила V20» (глава — запись, раздел — страница).

## Релиз

`node tools/release.mjs 0.7.0 "заголовок"` — проверит, что Foundry закрыт и правки закоммичены, поднимет версию,
пересоберёт компендии, прогонит tools/check.mjs, сделает коммит и тег и выложит архив и system.json на GitHub.
Заметки — из tools/release-notes.md (если есть), иначе список коммитов с прошлого тега.
На GitHub при каждом push запускается та же проверка (.github/workflows/check.yml).
